# PlannerSelector architecture — 2026-10-15

## Authorized intent
User explicitly requests command -> programmatic entity/keyword/argument extraction -> DB candidate retrieval -> selector LLM -> reuse via ScriptedPlanner / generation via configured ModelServerPlanner or InprocessModelPlanner / clarification. Preserve execution validation and adapter layer. Implement inline; no further approval gate. New subsystem, design recorded before code.

## Components
- plan_features.py: stdlib-only Unicode normalization, conservative Korean particle variants/action keyword aliases, numeric argument terms, state-known entity hints. These select candidates, never authorize execution. Preserve original command, negation and order for LLM.
- PlanStore schema v2: transactional v1 migration retaining IDs/bodies/hashes/success history, command aliases and indexed search terms. Rebuild old rows once. New/duplicate additions and successful outcomes keep aliases searchable without duplicating plans. Search indexed terms with bounded OR candidates, explicit entity boost and small result cap. Full candidate plans revalidated by get; no per-request full-plan scan, embedding dependency or arbitrary SQL from models.
- Generic complete(messages, schema, max_tokens, require_complete) on HTTP/inprocess model adapters; existing plan(context) delegates with unchanged mission schema. HTTP may constrain selector schema; inprocess uses prompt + strict post-validation, no claim of grammar constraints. Selection and generation may share a client/model, or configure separate clients. No heavy imports for HTTP/file/db paths.
- PlannerSelector.select(context): DB extraction/search then LLM JSON decision reuse/generate/clarify. Include complete shortlisted plan bodies, actual targets/order/conditions/criteria, aliases, permitted skills and compact state/request-goal context within bounded prompt budget; omit over-budget candidates whole, never silently truncate execution steps. Empty list still goes to LLM for ambiguity detection. Decision strictly validates; reuse ID must be one of shown candidates and the compared immutable snapshot is passed through ScriptedPlanner. Invalid/truncated/error decisions stop with PLANNER_ERROR, never silently pick or execute.
- planning_dispatch.py: shared dispatch for PlanGenerator/CoEgent, exposes selection callback and per-model before_call hook for remote policy gating. No mission JSON accepted from selector. Replanning/repair/continuation bypasses full-plan reuse and invokes configured generator with remaining-work context, avoiding repetition of completed effects.
- ClarificationRequired: PlanGenerator report NEEDS_CLARIFICATION / NOT_EXECUTED, plan=None, question. CoEgent same status and question; with no dispatched work, no skill or stop is issued. Existing cleanup still applies if side effects happened. No catalog success save.
- CLI --planner auto, --generation-planner http|hf; selector backend same|http|hf, independent endpoint/model/adapter options when requested. Default shares selected generation client. No automatic process/runtime choice by selector. Preserve old defaults and request mode. Optional Python planner_selector argument for existing APIs.

## Boundaries and limits
Natural language equivalence is LLM judgment, not proof. Deterministic features may miss candidates; this produces generation rather than arbitrary reuse. Selection never substitutes current plan/state/authority/freshness checks. Candidate prompt treats command/catalog as data; reasons bounded. Trace records features/candidate IDs/decision/selected planner, not secrets or all catalog rows. No live model load/inference required for test suite; CPU HTTP fixture exercises the real protocol, fake local model tests generic generation path. Quality with actual deployed models remains an explicit separate evaluation.

## Data and lifecycle
Existing default catalog migrates transactionally with data preserved. Tests isolate default DB. Selector work fits existing planner timeout and cancellation; candidate read may finish after cancellation but cannot execute. Keep per-call selection data local, no shared stale last-choice singleton. Preserve DB dedup and auto-save. No Git repo; changes confined to CoEgent_Agent plus CPU regression checks.
